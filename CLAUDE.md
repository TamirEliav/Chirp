# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Chirp is a real-time sound analysis and threshold-triggered recording desktop app for bioacoustics research. Built with Python/PyQt5 + pyqtgraph/OpenGL (v3.0.0 re-architecture). Organized as the `chirp/` package after the Phase 1 refactor (was previously a ~4200-line `chirp.py` monolith). Current version: v3.7.0.

## Running the App

```bash
conda activate chirp
python -m chirp      # preferred
# or: python chirp.py  (legacy shim at the repo root still works)
```

## Dependencies

```bash
pip install -r requirements.txt
```

Stack: sounddevice (audio I/O), numpy, scipy (DSP/filtering/WAV), PyQt5 + pyqtgraph/OpenGL (GUI/rendering; matplotlib only supplies the inferno colormap LUT), soundfile (streaming WAV writes). Conda env name: `chirp`.

## Building (PyInstaller)

The app is distributed as `dist/Chirp.exe` via PyInstaller. Entry point is `chirp.py` at the repo root (a 14-line shim that delegates to `chirp.main`). Build artifacts go in `build/` and `dist/`. Pass `--icon assets/chirp.ico --add-data "assets;assets"` so the app icon (generated by `scripts/make_icon.py`) ships with the exe.

## Architecture

The package layout (post Phase 3):

```
chirp/
├── __init__.py          re-export surface (42 lines)
├── __main__.py          python -m chirp entry point
├── constants.py         audio/display constants, Catppuccin palette, QSS
├── dsp/
│   ├── spectrogram.py   SpectrogramAccumulator
│   ├── filter.py        BandpassFilter
│   ├── envelope.py      analytic_envelope (Hilbert magnitude)
│   └── entropy.py       normalized_spectral_entropy
├── audio/
│   ├── capture.py       AudioCapture (sounddevice.InputStream wrapper)
│   ├── clock.py         DisciplinedClock — sample-index → UTC wall-time servo
│   └── devices.py       device enumeration + robust name matching (#21)
├── recording/
│   ├── trigger.py       ThresholdRecorder — sample-accurate state machine (#15)
│   ├── entity.py        RecordingEntity (per-stream data model + ingestion thread)
│   └── writer.py        WAV writer pool (non-daemon workers, #17)
├── config/
│   └── schema.py        settings build / load / round-trip + versioning (#22)
└── ui/
    ├── theme.py         re-export of C + QSS
    ├── sidebar.py       MiniAmplitudeWidget, RecordingSidebarItem, RecordingSidebar
    └── window.py        ChirpWindow + main()
```

Key classes in dependency order:

1. **AudioCapture** — Wraps `sounddevice.InputStream`; callback enqueues 1024-sample chunks to a queue.
2. **SpectrogramAccumulator** — Overlapped FFT computation (configurable window function and FFT size). Returns both dB column and linear magnitude (the latter used for spectral entropy).
3. **BandpassFilter** — 4th-order Butterworth IIR filter with lazy coefficient redesign.
4. **ThresholdRecorder** — Sample-accurate state machine managing threshold-triggered WAV recording with pre-trigger buffer, hold, post-trigger, and min_cross. Accepts per-sample `trigger_mask` for sub-chunk precision. WAV writes go through a non-daemon writer pool (#17).
5. **RecordingEntity** — Central data model for one audio stream. Owns an AudioCapture, SpectrogramAccumulator (display + optional analysis), BandpassFilter, ThresholdRecorder, and ring buffers. `ingest_chunk()` runs on a dedicated background thread (#19). Decoupled display and analysis FFT accumulators (#12). Serializable to/from dict for config persistence.
6. **MiniAmplitudeWidget** / **RecordingSidebarItem** / **RecordingSidebar** — Sidebar UI widgets for multi-stream management.
7. **ChirpWindow** (QMainWindow) — Top-level orchestrator. Manages multiple RecordingEntities, matplotlib-based visualization with blitting, and config file I/O. Supports three visualization modes (Spectrogram, Waveform, Both) and two layout modes (Config mode for editing, View mode for monitoring grid). Dynamic subplot layout builds axes based on display mode and whether spectral entropy is active.

### Data Flow

```
AudioCapture callback → queue → [ingestion thread] RecordingEntity.ingest_chunk() → {filter, FFT, spectral entropy, ring buffers, trigger state machine} → [main thread] ChirpWindow._update_plot() (50ms timer) → matplotlib blit
```

### Key Design Details

- **Ring buffers** use modulo-arithmetic write heads (`write_head`, `col_head`) for O(1) circular writes. Includes amplitude, spectrogram, and entropy buffers.
- **Frequency scales**: Linear, Log, and Mel modes via lookup-table interpolation in `rebuild_freq_mapping()`.
- **Min total crossing filter**: `min_total_cross_sec` (per stream, default 0 = off) discards a finished event whose *accumulated* above-threshold duration never reached the minimum — buffered events skip the writer pool, streamed events abort their `.tmp` (never published). Force-split part flushes are exempt (`splitting=True`); continuations inherit the parent's running `above_total`, so the criterion is judged once per event, on its final file. A dropped event is also flagged in the record strip: `process_chunk` reports its range in `discarded_spans` (separate from published `flushed_spans`), the entity paints those samples into `discard_mask_buffer` (clearing them from `record_mask_buffer`), and `pg_panel.events_rgba` renders the record row **red** instead of green so a dropped event is visually distinct from a saved one. See `tests/test_min_total_cross.py`, `tests/test_indicators.py`.
- **Remote-desktop resilience**: the capture watchdog's recovery runs on a background worker thread (never the GUI thread — PortAudio calls on a dead WASAPI device can block indefinitely); transient stalls un-latch when frames resume on their own; a global PortAudio refresh happens only when no healthy stream exists and after closing the monitor's output stream. Stop Acq CLOSES a live-device capture (releasing an exclusive WDM-KS pin while idle) and Start Acq opens a fresh stream instead of resuming a paused one — a stopped-but-open pin that idled through RDP session churn can refuse to restart; `resume()` failures fall back to one close+reopen, and a failed start latches `last_ingest_error` + the `!` badge instead of a silently dead button (see `tests/test_acq_restart.py`). The manual recommends WDM-KS input devices for RDP hosts (kernel-streaming pins live below the per-session endpoint layer that RDP churns). Rendering: `_gl_effective` clamps the configured `use_opengl` to raster while a Windows remote session drives the display (startup `SM_REMOTESESSION` check + mid-run `WM_WTSSESSION_CHANGE` viewport swap via `GraphicsView.useOpenGL`); AnyDesk-style screen mirroring is unaffected.
- **Amplitude trigger**: Per-sample `envelope >= threshold` mask, where envelope is the magnitude of the analytic signal (Hilbert transform of the bandpassed waveform). Chosen over `|x| >= threshold` because the latter dips to zero at every waveform zero crossing — for narrowband signals (pure tones, bandpassed calls) that reset `_above_streak` on every half-cycle and prevented `min_cross` from ever being satisfied. See `chirp/dsp/envelope.py` and `tests/test_envelope_trigger.py`.
- **Spectral entropy trigger**: Normalized Shannon entropy (0=pure tone, 1=white noise) computed from FFT magnitudes. Four modes: Amplitude Only, Spectral Only, Amp AND Spectral, Amp OR Spectral. Triggers when entropy falls *below* threshold. Entropy trace plot with draggable threshold appears when a spectral mode is active.
- **Stereo trigger modes**: Left Channel, Right Channel, Any Channel, Both Channels, Average — applies to both amplitude and entropy triggers.
- **Auto-calibrate**: Measures ambient noise to set threshold automatically.
- **Audio monitor gain**: `AudioMonitor.set_gain()` (0.0–2.0, unity 1.0) applied in the output callback with clip-on-boost; UI slider (0–200%) in the monitor bar.
- **Audio monitor channel**: the capture forwards only the column matching the stream's `channel_mode` to the monitor — `AudioCapture.set_monitor(monitor, source_id, channel)` where `channel` is 0 (Left/Mono), 1 (Right), or None (Stereo → both). `RecordingEntity._monitor_channel()` derives it from `channel_mode` and re-wires on every `_make_capture` rebuild, mirroring the display/record selection in `process_chunk`. Without it a 'Right' stream (opened with 2 input channels) fed both columns and the mono monitor averaged the left channel back in — so two streams splitting one stereo input (e.g. streams 3/4 = L/R) played each other's audio. See `tests/test_monitor.py`.
- **Audio monitor persistence**: the monitor bar's state (output device by name+hostapi, gain %, mute, follow, and source-by-list-position) is saved to the config's top-level `monitor` section and restored on load via `_build_monitor_settings` / `_apply_monitor_settings`. Output device is re-resolved by name (`_resolve_output_device`), source by index into `recordings` (-1 = Off). Restore order is gain/mute/follow → output device → source; a saved-muted config restores routing silently (output stays closed). Defaults live in `chirp.config.schema.DEFAULT_MONITOR`.
- **Per-stream color**: each `RecordingEntity.color` (hex, persisted; empty = unassigned) is a recognition accent. `_sync_stream_colors` assigns the first unused `constants.STREAM_COLORS` on add/load. Picked from the Config view via the STATUS-box "Color" swatch button (`_on_change_stream_color` → `QColorDialog`); `_refresh_stream_color_ui` syncs the button + panel frame on selection/change. Shown as: a **left-edge accent bar** on the sidebar item (`RecordingSidebarItem._apply_item_style`, no swatch), a **rectangle around the whole config plot panel** (`ConfigPlotPanel.set_color`, a scoped `QGraphicsView#config_plot_panel` border), and a **rectangle around each view-mode tile** (`StreamTile._apply_color`, scoped `QWidget#stream_tile` border, refreshed each tick in `update_all`). All three use objectName-scoped stylesheets + `WA_StyledBackground` so the border doesn't cascade into child widgets. The spectrogram keeps its fixed inferno colormap.
- **Per-stream enable switch**: `stream_enabled` (persisted, default True) — a disabled stream keeps its config but is skipped by Start All Acq / Start All Rec (its own buttons still work; Stop All reaches everything). Sidebar On/Off button (disabling stops the stream immediately) + "Enabled" row in the All-Streams table.
- **Per-stream parameter lock**: `params_locked` (persisted, default False) — a lock prevents accidental edits to a stream's *configuration* (trigger params, band filter, spectral trigger, output, reference date, input device, per-stream color, Reset, and inline rename), while **display params, the audio monitor, and transport (start/stop acq/rec) stay usable**. Two toggles kept in sync: a 🔒/🔓 icon on each sidebar item (`RecordingSidebarItem.set_params_locked`) and a "🔓 Unlocked / 🔒 Locked" button in the config STATUS panel (`_btn_lock_cfg`). Sidebar header also has **Lock All / Unlock All**. Enforcement: `ChirpWindow._apply_lock_ui(e)` `setEnabled(not locked)` on `self._lockable_widgets` and calls `ConfigPlotPanel.set_threshold_locked` (freezes the draggable amplitude/entropy threshold lines — the flag survives panel rebuilds); `_apply_lock_ui` runs at the end of `_load_params_from_entity` so it reflects the selected stream. **Unlocking is gated by a confirmation naming the stream** (`_confirm_unlock`, single or bulk) so one user can't silently unlock another's stream; locking needs no confirmation. The All-Streams table greys out a locked stream's non-exempt cells (`config_table._LOCK_EXEMPT_KEYS` = the display group + `stream_enabled`). See `tests/test_lock.py`, `tests/test_config_panel.py` (threshold freeze), `tests/test_config_schema.py` (persistence).
- **Display modes**: `display_mode` on RecordingEntity controls subplot layout — 'Spectrogram' (default), 'Waveform' (raw signed audio in teal), or 'Both'. The subplot grid is rebuilt dynamically in `_rebuild_axes()`.
- **Config format**: JSON with a `recordings` array, a `view_mode` object, and a `monitor` object. Also reads legacy `.chirp` files. v1.1.0 added `spectral_trigger_mode`, `spectral_threshold`, and `display_mode`. Later optional additions (no schema-version bump; older files omit them and get defaults): `view_mode.use_opengl`, `view_mode.active_only`, `view_mode.fill_order`, the whole `monitor` section, and per-recording `color` + `params_locked`.
- **View-mode grid fill order**: `view_mode.fill_order` ('column' default / 'row') controls tile placement — column-major fills down the first column (streams 1..rows) before the next, so 8 streams in 2 columns land 1–4 / 5–8. Pure mapping in `central_plots.grid_cell(i, n, cols, fill_order)`; exposed as the "Order" combo in the view toolbar. See `tests/test_pg_window_integration.py`.
- **Startup config preference**: `chirp/config/startup.py` — a `QSettings`-backed choice (`empty` / `last` / `file`) for what `ChirpWindow.__init__` loads at launch (`_apply_startup_config`, after the timer exists since a load stops/restarts it). `empty` seeds one fresh recording; `last` reloads the most recently saved/loaded file (`_remember_last_config` persists it on every save + load); `file` loads a pinned path. Any miss/failure falls back to `_add_recording()`. The "⚙ Startup" button (`_open_startup_prefs`) edits the preference. The preference lives outside any config file so it survives before a config exists and doesn't travel with a shared file.
- **WAV filename tokens**: `writer._compose_filename` composes `<prefix>_<epoch_ms>_<localts>_<suffix>.wav` from the user's prefix/suffix fields ONLY — the stream name is deliberately excluded (only prefix/suffix decorate the name). Same-millisecond collisions between streams are resolved by `_dedup_target`'s `_rNN` token, not by embedding the stream name. `filename_stream` is still threaded through the writers, but only for error-log identification and the timestamp-divergence watchdog. See `tests/test_writer.py`, `tests/test_filename_hygiene.py`.
- **Config-area layout** (`ChirpWindow._build_ui`): the window is split by two draggable `QSplitter`s — a horizontal one between the sidebar and the right pane (`_main_splitter`; the sidebar uses `setMinimumWidth`, not a fixed width, so it's resizable) and a vertical one between the display plots and the config area (`_plot_config_splitter`). The config row is `CONTROLS | TRIGGER | DISPLAY | right-stack`: `_build_controls_box` (transport buttons), `_build_params` (trigger), `_build_spec_params` (**DISPLAY laid out as a single label|control column** to stay narrow), and `_build_config_right_stack` — the stretched right column that stacks **STATUS, OUTPUT, REFERENCE DATE, INPUT DEVICE** vertically as wide horizontal panels. STATUS (`_build_status_box`) is a compact `QGridLayout` — the four ACQ/REC/TRIG/ENT readouts in a 2×2 block (grid, not a single row, so they never overlap when the right column is narrow) with the lock toggle + small color swatch in a third column. View mode hides/show the whole config area as one splitter child (`_config_widgets = [config_container]`).
- **Styling**: Catppuccin Mocha dark theme via embedded QSS; Consolas monospace font for labels. Teal (`#94e2d5`) for waveform, peach (`#fab387`) for entropy threshold.
- **Filename timestamps (disciplined clock)**: WAV onsets derive from `DisciplinedClock` (`chirp/audio/clock.py`) — a free-running sample clock (ring-absolute frame index / rate) steered onto wall time, NTP-style. The PortAudio callback records one `(ring.write_total, time.time())` observation per buffer; the ingest thread filters them with a windowed MINIMUM (callback delivery noise is one-sided late) and slews the correction at ≤1 ms per second of audio (1000 ppm ≫ any crystal error, so drift is tracked with no explicit rate term and adjacent/split files stay sample-aligned). Forward STEPs (capture holes > 2 s: device stall, drop burst) happen only when no recording event is open (`ThresholdRecorder.has_active_events`) and are logged as `clock_step`; backward steps never happen. The clock is UTC-aware internally; the filename's local token is converted in `writer._compose_filename` (DST-safe mid-session). Fallback when no observations exist (WAV playback, tests): the M5 anchor stamped at `start_acq` plus the cumulative sample counter. INVARIANT: `_samples_total` is monotonic while acquisition runs; display-only operations (`reset_display`, `change_display_seconds`) clear buffer contents but never touch the counter or cursors. Anything that legitimately zeroes the counter (sample-rate change) must invalidate the wall anchor in the same breath; the clock+ring pair is recreated together in `_make_capture`. See `tests/test_disciplined_clock.py`, `tests/test_timestamp_clock.py`.
- **Timestamp watchdog + audit trail**: `writer.TIMESTAMP_DIVERGENCE_SEC` (10 s; `None` disables — the test-suite default via conftest) — at every WAV publish, `onset + duration` is compared against the wall clock; divergence flags the pool error stats (sidebar badge) and logs `timestamp_divergence`. `chirp_clock_log.csv` (in each stream's base output dir, one row/min/stream via `RecordingEntity._queue_clock_log_row` → writer pool) records ring sample index, derived capture epoch + source (`clock`/`anchor`), and raw wall epoch, so filename timestamps of long runs can be verified or corrected offline. Capped at 64 MB; appends run on writer-pool workers, never the ingest thread.
- **Sample rate changes** require full pipeline rebuild (capture, filters, buffers, display).
- **Saturation detection**: clips at ≥ 0.99 of full scale, turns amplitude plot red.
- **Scroll-wheel zoom**: Mouse-centered zoom on entropy, waveform, and spectrogram axes.
- **User manual**: `manual.html` is a standalone HTML manual included in the repo.
